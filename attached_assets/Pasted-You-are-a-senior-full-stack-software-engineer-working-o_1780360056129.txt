==================================================
BACKEND API REQUIREMENTS
==================================================

Add backend routes/services for Practice Mode.
Use the current project route style and authentication middleware.

Required endpoints:

1. Generate practice session

POST /api/practice/generate

Body:
{
  "course_id": number,
  "topic_id": number optional,
  "subtopic_id": number optional,
  "session_type": "topic" | "subtopic" | "weak_area" | "mistakes" | "retry_incorrect",
  "question_count": number
}

Behavior:
- Only students can call this endpoint.
- Verify the course is visible to the student.
- Student course visibility must respect Strategy A:
  student program + enrollment + existing course_offering + active course
- Use only approved questions.
- Exclude archived, draft, and pending questions.
- For topic practice:
  filter by course_id and topic_id.
- For subtopic practice:
  filter by course_id, topic_id, and subtopic_id.
- For mistakes practice:
  use questions the student previously answered incorrectly.
  Sources:
  1. practice_session_questions where is_correct = false or earned_score < max_score
  2. mock_exam_questions where is_correct = false or earned_score < max_score
- Avoid duplicate questions inside the same practice session.
- Randomize selected question order.
- Randomize answer option order per question.
- Store randomized_option_order.
- Create practice_sessions row.
- Create practice_session_questions rows.
- Return the created practice_session id and basic metadata.

If no questions are available:
Return a clear message and do not create an empty session.

Examples:
- No approved questions for selected topic
- No previous mistakes available
- Not enough questions available

2. Get practice session

GET /api/practice/:sessionId

Behavior:
- Only the owner student can access the session.
- Return session metadata.
- Return questions in stored question_order.
- Return answer options in stored randomized_option_order.
- Do not reveal correct answers before the student submits an answer.
- If a question was already answered, include:
  - selected answers
  - is_correct
  - earned_score
  - max_score
  - confidence_level
  - explanation_text
  - correct answer ids

3. Submit one practice answer

POST /api/practice/:sessionId/submit-answer

Body:
{
  "question_id": number,
  "selected_answer_option_id": number optional,
  "selected_option_ids": number[] optional,
  "confidence_level": "low" | "medium" | "high",
  "response_time_seconds": number optional
}

Behavior:
- Only the owner student can submit answers for the session.
- Validate that the question belongs to the session.
- Validate that the selected answer option ids belong to that question.
- Validate confidence_level.
- Grade the answer immediately.
- Save:
  - selected_answer_option_id for single-choice if used
  - selected_option_ids for multiple-choice or general answer storage
  - is_correct
  - confidence_level
  - response_time_seconds
  - max_score
  - earned_score
  - answered_at
  - status = answered
- Update practice_sessions:
  - answered_count/correct_count if such fields exist
  - updated_at
- Return immediate feedback:
{
  "is_correct": boolean,
  "max_score": number,
  "earned_score": number,
  "correct_answer_ids": number[],
  "explanation_text": string,
  "feedback": string
}

4. Finish practice session

POST /api/practice/:sessionId/finish

Behavior:
- Only the owner student can finish the session.
- Set status = completed.
- Set completed_at.
- Return summary:
  - total_questions
  - answered_questions
  - correct_answers
  - earned_score
  - total_possible_score
  - accuracy_percentage
  - low_confidence_count
  - incorrect_count

5. Practice history

GET /api/practice/history

Behavior:
- Only students can access their own practice history.
- Return:
  - completed sessions
  - active unfinished sessions
  - course name
  - topic/subtopic names if available
  - status
  - created_at / completed_at
  - summary numbers

6. Continue unfinished session

This can use:
GET /api/practice/:sessionId

Also provide active sessions in:
GET /api/practice/history

7. Generate retry incorrect practice

Either reuse:
POST /api/practice/generate

with:
{
  "session_type": "retry_incorrect" or "mistakes"
}

Behavior:
- Pull previously incorrect questions from practice and mock exam history.
- Use only questions that still exist and are approved.
- Exclude archived/draft/pending questions.

==================================================
EDGE CASES TO HANDLE
==================================================

1. Student selects topic with no approved questions
Show message and do not create session.

2. Student selects more questions than available
Either:
- cap to available count with clear message
or
- block and ask to choose lower number.

3. Student has no previous mistakes
Show empty state:
No previous mistakes are available yet.

4. Student tries to access another student’s session URL
Return forbidden / redirect.

5. Student refreshes practice page after answering some questions
Previously answered state must persist.

6. Student exits session before finishing
Session remains active and appears under Continue Unfinished Practice.

7. Question has multiple correct answers
Support selected_option_ids and partial scoring.

8. Question has single correct answer
Support selected_answer_option_id or selected_option_ids with one item, depending on current code style.

9. Archived/draft/pending question appears in old history
Do not include it in newly generated practice sessions.

10. Deleted/missing answer option from old history
Handle gracefully without crashing.

11. User has no confidence selected
Show validation message or default to medium.

12. Duplicate questions from both practice mistakes and exam mistakes
Deduplicate by question_id.
