==================================================
PERFORMANCE CALCULATION REQUIREMENTS
==================================================

Create a backend analytics service that can calculate performance summaries for a student.

Use data from:
1. mock_exams + mock_exam_questions
2. practice_sessions + practice_session_questions
3. questions table for course_id, topic_id, subtopic_id, difficulty_level

Data to aggregate:
- attempts_count
- correct_count
- incorrect_count
- total_earned_score
- total_possible_score
- accuracy_rate
- average_response_time
- low_confidence_count
- repeated_mistake_count
- last_activity_at

Counting rules:
- Each answered question attempt counts as one attempt.
- Correct if is_correct = true or earned_score = max_score.
- Incorrect if is_correct = false or earned_score < max_score.
- If max_score / earned_score is missing, fallback to is_correct.
- If response_time_seconds is missing, ignore it from average_response_time.
- If confidence_level = low, count it in low_confidence_count.
- repeated_mistake_count should count repeat wrong attempts for the same topic/subtopic after the first wrong attempt.

Minimum data rule:
Do not classify a topic/subtopic as weak unless it has enough attempts.
Suggested minimum:
- attempts_count >= 3

If attempts_count < 3:
- weakness_level should be strong or needs_practice only if needed
- Do not mark as weak based on too little data
- Recommendations can say “Practice more to generate better insights” only if the UX needs it, but do not create fake weak areas

==================================================
WEAKNESS SCORE REQUIREMENTS
==================================================

Implement a simple transparent weakness score.

Suggested formula:

incorrect_rate = incorrect_count / attempts_count

weakness_score =
(incorrect_rate * 60)
+ (repeated_mistake_factor * 20)
+ (low_confidence_factor * 10)
+ (slow_response_factor * 10)

Where:
- incorrect_rate is between 0 and 1
- repeated_mistake_factor is normalized between 0 and 1
- low_confidence_factor is low_confidence_count / attempts_count
- slow_response_factor can be 0 if there is no reliable benchmark
- final weakness_score must be clamped between 0 and 100

Suggested weakness levels:
- 0 to 39 = strong
- 40 to 69 = needs_practice
- 70 to 100 = weak

Important:
The student UI should not display the formula.
The student UI should show:
- Strong
- Needs Practice
- Weak
- Accuracy
- Attempts
- Repeated mistakes
- Practice Now button

==================================================
RECOMMENDATION GENERATION REQUIREMENTS
==================================================

Generate recommendations based on performance_summary.

Rules:
1. For weakness_level = weak:
   - Create or update high priority recommendation.
   - Type: practice_topic or review_subtopic.
   - Text should clearly explain what to practice.
2. For weakness_level = needs_practice:
   - Create or update medium priority recommendation.
3. For repeated_mistake_count > 0:
   - Create or update retry_mistakes recommendation.
4. Do not create duplicate active recommendations for the same user/course/topic/subtopic/type.
5. If a recommendation already exists and is active:
   - update its text/priority/updated_at instead of duplicating.
6. If performance improves, either:
   - mark the old recommendation as completed, or
   - lower its priority.
7. Recommendations must only refer to approved/non-archived questions where relevant.

Example recommendation texts:
- “Practice Nested Loops because your accuracy is 42%.”
- “Retry previous mistakes in Pointers to reduce repeated errors.”
- “Review SQL Joins because this topic needs more practice.”

EDGE CASES TO HANDLE
==================================================

1. No practice/exam history
Show empty state, no crash.

2. Not enough attempts
Do not mark topics as weak too early.
Show “Complete more practice to generate insights.”

3. Balanced performance across topics
Do not falsely mark a weak topic.
Show neutral or empty state.

4. Existing old mock exam rows with missing score fields
Fallback to is_correct.

5. Existing rows with missing response_time_seconds
Ignore missing values in average response time.

6. Multiple-choice partial scores
Use earned_score < max_score as incorrect/needs improvement if available.

7. Recommendation duplication
Do not create duplicate active recommendations for same user/course/topic/subtopic/type.

8. Improved performance after more practice
Update recommendation priority or complete old recommendations.

9. Student opens another student’s recommendation URL
Return forbidden.

10. Weak area points to a question/topic that was archived/deleted
Handle gracefully.
Do not generate Practice sessions from unavailable questions.

11. Course no longer visible to student
Do not show weak areas/recommendations for inaccessible courses.

12. Practice Now finds no approved questions
Show clear message.

13. Recalculate called multiple times
Should be idempotent:
- no duplicate summaries
- no duplicate recommendations
