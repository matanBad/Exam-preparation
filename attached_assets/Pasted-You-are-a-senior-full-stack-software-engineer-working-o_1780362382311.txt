- If no data exists, return empty arrays and null/0 values gracefully.

4. Student Readiness Score
--------------------------------------------------

Endpoint:
GET /api/analytics/student/readiness-score

Student only.

Implement a simple, demo-ready readiness calculation.

Suggested formula:
readiness_score =
average_accuracy * 0.45
+ recent_progress_score * 0.20
+ weak_area_adjustment * 0.20
+ practice_consistency_score * 0.15

Where:
- average_accuracy is based on submitted exams + completed practice sessions.
- recent_progress_score is based on the trend of recent scores.
- weak_area_adjustment decreases score when there are many weak areas.
- practice_consistency_score increases score when the student has recent practice activity.

Clamp readiness_score between 0 and 100.

Labels:
- 0–39: Needs significant practice
- 40–69: Getting there
- 70–84: Good progress
- 85–100: Exam ready

Do not show the formula in the UI.
Only show:
- percentage
- label
- short explanation

If insufficient data:
Return:
{
  "readiness_score": null,
  "readiness_label": "Not enough data",
  "message": "Complete more exams or practice sessions to calculate readiness."
}

EDGE CASES TO HANDLE
==================================================

1. Student has no exams or practice history
Show empty dashboard analytics state, no crash.

2. Student has practice but no exams
Readiness and progress should still use practice data if enough exists.

3. Student has exams but no practice
Analytics should still work from mock exams.

4. Student has fewer than 3 topic attempts
Do not overstate weak/strong conclusions.

5. Balanced topic performance
Do not falsely mark weak topics.

6. Missing score fields in old exam rows
Fallback to is_correct.

7. Missing response_time_seconds
Ignore from averages.

8. Multiple-choice partial credit
Use earned_score / max_score when available.

9. Lecturer has no course activity
Show empty state:
“No class activity data yet.”

10. Lecturer tries to open analytics for a course they do not teach
Return forbidden.

11. Problematic question has low attempts
Do not flag it until attempts_count >= 5.

12. Archived questions appear in historical answers
Handle gracefully.
Do not crash.
Do not recommend editing archived questions unless current UI supports it.

13. Dashboard API returns partial data
UI should not crash if one section is empty.

14. Recalculation is delayed
Dashboard should still render from current available data.
